# L1 — 用例场景总览 | LocalStream

## 系统简介

LocalStream 是一个运行在单台机器上的流式计算引擎，面向开发者提供简洁的流水线编程接口。用户通过 Java 代码描述数据处理流程（DAG），系统负责长期运行该流程、定期保存状态、支持从历史状态恢复，并提供实时的数据指标监控。

---

## 业务角色

| 角色 | 描述 |
|------|------|
| 流水线开发者 | 使用 LocalStream 编写数据处理逻辑的 Java 开发者 |
| 系统运维者 | 负责启停任务、管理 Checkpoint、监控任务状态的人员（可与开发者同为一人） |
| 观测用户 | 通过浏览器访问系统内置 Web 页面，查看任务运行状态和数据指标的人员 |

## UC-001 — 编排数据处理流水线

**目标**：开发者通过代码描述一条或多条数据处理路径，形成有向无环图（DAG）结构。

**前置条件**：
- 开发者已编写好自定义的数据源和数据输出逻辑

**主流程**：
1. 开发者创建一个流处理环境
2. 向环境注册一个或多个数据来源
3. 对数据流依次施加处理操作：
   - 转换：将每条数据映射为另一种形态
   - 过滤：按条件筛选数据
   - 按键聚合：将相同键的数据合并，产生聚合结果
   - 合流：将两条数据流合并为一条
4. 将处理后的数据流连接到一个或多个输出目标
5. 流水线描述完成，等待启动

**异常场景**：
- 若开发者在流水线中引入了循环依赖，系统应在启动时拒绝执行并提示错误

**验收标准（Given-When-Then）**：

```
Given 开发者已准备好数据源和输出目标的实现
When  开发者通过 API 依次描述：source → map → filter → keyby → sink
Then  系统内部形成一张合法的 DAG 结构，可供后续启动使用
```

## UC-002 — 启动流水线任务

**目标**：开发者一键启动已编排好的流水线，系统开始持续从数据来源读取数据并处理。

**前置条件**：
- 流水线已完成编排（UC-001 完成）

**主流程**：
1. 开发者调用启动命令
2. 系统验证 DAG 合法性（无循环、来源和输出目标存在）
3. 系统初始化各节点，分配必要资源
4. 系统启动所有数据读取线程，开始持续消费数据
5. 数据经过 DAG 节点流转并最终写出
6. 任务进入长期运行状态，直至手动停止

**异常场景**：
- 若 DAG 验证失败，系统停止启动并输出错误信息
- 若某个节点初始化失败，系统停止整个任务并输出原因

**验收标准**：

```
Given 一条合法的流水线已编排完成
When  开发者调用启动命令
Then  所有数据来源开始持续读取数据，数据依次流过各处理节点并写出到输出目标
And   任务在后台持续运行，不自动退出
```

## UC-003 — 数据流经 DAG 节点处理

**目标**：系统按照开发者定义的处理链路，将每条数据逐步经过转换、过滤、聚合等节点后，最终输出到目标。

**前置条件**：
- 流水线任务已在运行中

**主流程**：

### 转换（map）
1. 节点从上游接收一条数据
2. 将该数据按开发者定义的规则转换为另一种形态
3. 将转换后的数据发往下游节点

### 过滤（filter）
1. 节点从上游接收一条数据
2. 按开发者定义的条件判断是否保留
3. 若保留则发往下游，否则丢弃

### 按键聚合（keyby）
1. 节点从上游接收一条数据
2. 按开发者定义的键提取规则确定该数据所属的分组
3. 将同一分组的数据按开发者定义的聚合规则合并，维护中间聚合状态
4. 将最新的聚合结果发往下游节点
5. 聚合状态纳入 Checkpoint 保护范围

### 合流（union）
1. 节点接收来自两条上游流的数据
2. 将两条流的数据合并为一条流
3. 将合并后的数据发往下游

**验收标准**：

```
Given 数据来源持续产生数据
When  数据经过 map → filter → keyby 链路
Then  每条数据被正确转换、按条件过滤，相同 key 的数据被正确聚合后输出
```

## UC-004 — 触发 Checkpoint 保存状态

**目标**：系统周期性地收集所有有状态节点的内部状态并持久化，以便故障后能够恢复。节点只需将状态交给系统提供的 Checkpoint 接口，存储介质由系统负责（当前为本地磁盘，后续可扩展为远端存储）。

**前置条件**：
- 流水线任务已在运行中
- 至少存在一个有状态节点（如 keyby 聚合节点）

**主流程**：
1. 系统计时器到达设定的 Checkpoint 周期
2. 系统通知所有有状态节点开始保存状态
3. 各有状态节点将自身当前状态提交给系统提供的 Checkpoint 接口，节点不感知底层存储细节
4. 系统将收集到的所有节点状态持久化到存储介质
5. 所有节点的状态持久化完成后，系统记录本次 Checkpoint 完成标记（包含时间戳和版本号）
6. Checkpoint 完成

**异常场景**：
- 若某节点状态提交失败，系统记录错误日志，但不中断任务运行，等待下一次 Checkpoint
- 若系统持久化失败，同样记录错误日志，不中断任务

**验收标准**：

```
Given 一个含有 keyby 聚合节点的流水线正在运行
When  Checkpoint 周期到达
Then  聚合节点通过 Checkpoint 接口提交状态，由系统完成持久化
And   节点本身无需关心状态写入哪种存储介质
And   Checkpoint 完成标记被记录，包含版本号和时间戳
```

## UC-005 — 从 Checkpoint 恢复任务

**目标**：系统运维者在任务中断后，能够指定某个历史 Checkpoint 版本重新启动任务，从上次保存的状态继续处理数据。

**前置条件**：
- 本地磁盘存在至少一个合法的 Checkpoint 记录

**主流程**：
1. 运维者指定一个 Checkpoint 版本（或选择最新版本）启动任务
2. 系统从磁盘加载该 Checkpoint 的状态数据
3. 系统将各有状态节点恢复到对应的历史状态
4. 系统从数据来源继续消费后续数据（从 Checkpoint 时刻之后）
5. 任务恢复正常运行

**异常场景**：
- 若指定版本的 Checkpoint 文件损坏或不存在，系统提示错误，不启动任务

**验收标准**：

```
Given 存在一个合法的 Checkpoint 记录，其中 keyby 节点的聚合状态非空
When  运维者指定该 Checkpoint 启动任务
Then  keyby 节点的聚合状态被正确还原
And   任务继续从数据来源读取并处理后续数据
```

## UC-006 — 查看数据流指标

**目标**：系统运维者能够实时或周期性地查看每个数据来源读取了多少条数据、每个输出目标写出了多少条数据。

**前置条件**：
- 流水线任务已在运行中

**主流程**：
1. 系统在每个数据来源节点持续计数已读取的数据条数
2. 系统在每个输出目标节点持续计数已写出的数据条数
3. 运维者查询当前指标数据
4. 系统返回各节点的读取/写出计数

**验收标准**：

```
Given 流水线任务正在运行，数据持续流过
When  运维者查询指标
Then  系统返回每个 Source 节点的读取计数和每个 Sink 节点的写出计数
And   计数值随任务运行持续增长
```

## UC-007 — 通过 Web 页面观测任务与指标

**目标**：开发者或运维者（可为同一人，也可为不同人）通过浏览器访问系统内置 Web 页面，无需额外工具即可实时查看任务运行状态、数据处理拓扑结构和各节点实时吞吐趋势。

**前置条件**：
- 流水线任务已在运行中
- 系统内置 Web 服务已随任务一同启动

**主流程**：
1. 开发者或运维者在浏览器中输入系统地址（如 `http://localhost:8080`）
2. Web 页面展示当前运行中任务的基本信息：任务名称、启动时间、当前状态
3. 页面展示任务的 DAG 拓扑图：
   - 每个节点以图形方式呈现，节点名称能直接体现其功能（例如名称中含有 source、map、agg、union、sink 等语义关键词）
   - 数据输入节点（Source）与数据输出节点（Sink）在视觉上有明显区分，一目了然
   - 节点之间以连线体现数据的流动方向
4. 页面展示所有节点的输入数据总条数和输出数据总条数，节点按数据流的处理顺序排列（从上游到下游）
5. 每个节点旁展示一条最近 10 分钟的数据吞吐趋势曲线，帮助观测者直观感知该节点的处理速率变化
6. 页面展示各 Checkpoint 状态摘要
7. 页面展示近期运行日志
8. 页面每 5 秒自动刷新一次全部数据，无需手动操作

**角色说明**：
- 在小型项目中，开发者与运维者通常是同一人；在团队协作中，开发者关注流程正确性，运维者关注运行稳定性，均可独立使用此页面

**异常场景**：
- 若端口被占用，任务启动时打印警告，Web 服务降级为不可用，不影响数据处理

**验收标准**：

```
Given 一个流水线任务正在运行，DAG 包含 source → map → keyby → sink 链路
When  观测者打开浏览器访问 Web 页面

Then  页面展示任务名称、启动时间和运行状态
And   页面展示 DAG 拓扑图，节点名称体现其功能（source/map/agg/sink），
      数据输入节点与输出节点在视觉上可区分，连线体现数据流向
And   页面展示所有节点（含中间算子）的输入/输出数据总条数，
      顺序与数据处理顺序一致（从 source 到 sink）
And   每个节点旁展示最近 10 分钟的吞吐率趋势曲线
And   上述数据每隔 5 秒自动刷新一次，无需用户操作
```
